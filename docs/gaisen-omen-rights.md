# 神殿スロット trial-2：前兆の当選権利を保つ

2026年10月31日。Draft PR120の継続作業です。運営用無料試遊のみで、本番合流・一般公開・実財布接続は保留です。

## 問題と今回の変更

fd275bbまでは、通常の抽選で当たると`omen`（前兆の残りG）だけを保存し、前兆が終わる瞬間にGGを1セット追加していました。途中でGODや履歴当選からGGを開始すると`startGG`が`omen`を0へ戻すため、先に当たった1セットが消えていました。赤7・G-STOPを挟んだ復帰でも同じ問題がありました。

新版では`omenStocks`で前兆中の確定権利を別に保持します。残りGが進んでも権利は減らさず、GG開始時に通常のストックへ一度だけ移します。GGの初当たり数・当選演出・シミュレーションの移管済みセット数は従来どおり実際にストックへ移った時点で集計します。前兆の権利だけで払出やポイントを増やしません。

| 状況 | 新版の結果 |
| --- | --- |
| 通常抽選で1セット当選→前兆終了 | 1セット開始、残り0 |
| 前兆中にGOD | 前兆1＋GOD5＝6セット。1セット開始、残り5 |
| 前兆中に赤7 | 前兆1を保持したままSGGへ。SGG後に赤7分と一緒にGGへ移管 |
| 前兆中または終了ゲームに黄7履歴当選 | 前兆1＋履歴1＝2セット |
| 前兆中にG-STOP→ハズレ | 前兆の残りGと1セット権利を保持して復帰 |
| 前兆中にG-STOP→当選 | 前兆分とG-STOPの当選分を合算してGGへ。次のG-STOP待機でも再加算しない |
| 前兆中に従来の天井カウンタへ到達 | 既存の当選1セットを開始。追加の天井当選として二重加算しない |

天井の扱いは現行試遊での二重加算防止です。実機の1480G＋前兆やループ振分を精密に実装したという意味ではありません。

## 保存と互換性

- `trial-1`は従来の抽選列・保存形式・進行を維持します。修正は`trial-2`だけです。
- 以前の`trial-2`保存に`omenStocks`がなく、`omen`が正なら確定権利1セットとして読みます。STOP確定時に明示化し、その後のJSON再保存/読込では増やしません。
- G-STOP/SGGへの退避中やリール停止途中でも同じ補完を行います。明示的な0は補完しません。
- すでに前兆が消えた過去の遊技は復元できません。履歴の文字列を根拠に補填したり、本番DBを書き換えたりしません。
- 前兆を本人用に保存し、別台で旧設定のまま再開します。受入台の状態・設定予約とは別に保持します。
- 内部モード、前兆残りG、`omenStocks`を画面モデルへ追加公開しません。表示は既存の前兆演出と、GG移管時の実際の獲得数です。

## 運営用の確認

開発版の新版無料試遊へ着席し、「場面を選んで動作確認」→「前兆（当選済み）」を選ぶと残り5G・当選分1セットから開始します。離席・別台再開も試せます。場面確認にはsample印を付け、自然抽選の収支として扱いません。回転途中・保存分の再開中には場面を入れ替えられません。

GOD等の強制成立は一般のWeb入力には追加していません。重複条件はエンジンのテスト、および使い捨てDBに保存済み役を固定するWebテストで検証します。

## 検証と試算

`test/gaisenOmen.test.ts`で通常当選、前兆満了/GOD/赤7/履歴/G-STOP/天井との重複、保存互換、停止途中の再読込、二重STOP、期限・別台・設定予約・内部状態の非公開を確認します。`test/gaisenWeb.test.ts`では新版の場面選択→離席→別台再開→同時STOPを実ルートで通し、6セットの保全と実財布不変を検証します。

全体検証で既存の競馬日付境界テストに、固定の判定日時とDBの実行日時のずれを確認しました。`test/keibaPurseDouble.test.ts`の使い捨てDBだけ記録時計を入力日時に合わせ、日額上限・日付切替直後の再上限と記録時刻を検証しています。競馬の本番コード、設定、支払額は変更していません。

最終結果：型チェック・ビルド成功。`npm test -- --maxWorkers=4 --testTimeout=60000`は全219ファイル2,427件成功（617.54秒）。初回の全件で日付依存を検出し、修正後に全件を再実行しています。テストの削除やskipは行っていません。

現行ソースでの自然抽選試算は次のコマンドです。DBや設定には接続しません。

```sh
node --import tsx src/scripts/gaisen-phase-audit.ts > /tmp/gaisen-omen-audit.json
```

設定1〜6、100万G×3seedと10万G×3seed×3押し順、合計2,340万G。結果は`gaisen-omen-audit.json`へ保存し、前段階の`gaisen-history-audit.json`を上書きしません。終了時の`unfinished.omenStocks`は未消化権利として記録し、払出や移管済みの`awardedSets`には含めません。`awardedSets = startedSets + unfinished.stocks`という従来の集計関係も維持します。
