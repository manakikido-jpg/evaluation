# イベントの声を別のVCへ中継する

ステージの**人の登壇者の声**を、通常VCの1〜6部屋に流します。**拾を受信専用に固定し、壱〜玖の空いているBOTから配信用を選びます。** 中継していない間も拾は通常の読み上げに使いません。10体構成で、6部屋へ中継中も残り3体は別の部屋の読み上げに使えます。Windows PCで音を取り込む操作は不要です。

**導入後、必ず1部屋で実際の音を確認してから6部屋に広げてください。** 自動テストはDiscord接続の代わりにはなりません。今回の開発環境からは本番VPS・Discordの音声へ接続しておらず、実通話は未検証です。時刻による自動開始はありません。

## 運用担当が反映する

1. 本番担当がこの変更のPRを確認・合流し、VPSに変更が届いたことを確認します。メインBOTの自動デプロイだけで専用の読み上げサービスまで更新済みとは判断しません。
2. 稼働中の読み上げを中断してよい時間に、VPSのリポジトリで `sudo bash scripts/read-aloud.sh up` を実行して**専用サービス**を作り直します。既存の専用環境変数と10体のBOTを使い、新しいトークンや設定項目は不要です。拾は既存の `READ_ALOUD_BOT_TOKENS` の**10番目**です（設定スクリプトは壱〜拾の順）。表示名やニックネームで判定しません。10番目がない場合は中継を開始せず、壱〜玖で代用しません。別のプロセスを同じトークンで同時起動しません。
3. `sudo bash scripts/read-aloud.sh ps` で状態、必要なら `logs` で起動結果を確認します。秘密の環境変数を表示する操作は不要です。Discordで先頭の読み上げBOTの `/イベント中継` が選べることを確認します。

反映は本番担当の作業です。この手順を書いたことは、反映や再起動を実行したことを意味しません。

## 開始前に確認する

- 操作する人にはDiscordの**サーバー管理（Manage Server）権限**が必要です。対象サーバーで、自分が閲覧・接続できる部屋だけを指定します。
- ステージのイベントを開始し、発表する人が登壇していることを確認します。客席・BOT・ミュート中の人の声は取り込みません。
- 拾にはステージの**チャンネルを見る・接続・メッセージを送信**、壱〜玖には各配信先VCの同じ権限と**発言**を許可します。壱〜玖にはステージへの接続・発言権限は不要です。コマンドを受け付ける壱には対象チャンネルの閲覧を許可してください。BOTに管理者権限は不要です。拾は客席のままで使い、登壇させる必要はありません。
- 配信先は通常VCです。AFK・ステージ・重複する部屋は選べません。部屋の接続人数やDiscord側の制限で接続できない場合もあります。
- 対象の部屋で読み上げが動いている場合は、その部屋で `/読み上げ 停止` を使います。中継に必要なBOT数が空いていない場合は開始しません。ほかの部屋からBOTを勝手に移動させません。
- 発表者には、指定した別室にも声が届くことを先に伝えてください。開始時にはステージと配信先のチャットへ中継の案内が出ます。

## まず1部屋で確認する

1. `/イベント中継 開始` を選び、`ステージ` と `配信先1` を指定します。
2. 登壇者が話し、確認役が**配信先VCに入って実際に聞く**ことで確かめます。2人が同時に話す場合も確認してください。
3. `/イベント中継 状態` で受信の拾、各部屋の配信BOT、受信パケット数・最後に受信した時刻を確認します。受信数が増えても、各配信先で聞こえることまでは証明できません。
4. 登壇者が客席へ戻ると声が止まり、別の人が登壇するとその声が届くことを確認します。配信先で話した声はステージや別室へ送りません。
5. `/イベント中継 停止` を使い、音が止まり、使っていた2体が退出することを確認します。

入力の例（部屋名は実際の選択肢から選ぶ）：

```text
/イベント中継 開始 ステージ:イベントステージ 配信先1:確認用VC
/イベント中継 状態
/イベント中継 停止
```

## 6部屋へ広げる

1部屋の確認後に停止し、もう一度 `/イベント中継 開始` で `配信先1`〜`配信先6` を選びます。途中で部屋を追加・変更するときも、停止してから開始し直します。

本番前に全6部屋で聞こえることを確認し、10分ほど通して試してください。別の部屋では残り3体で通常の読み上げが使えることも確認します。中継中の部屋は読み上げを同時使用できません。音量は配信BOTのユーザー音量で各自調整できます。

## 止まった・聞こえないとき

- 権限不足の返事には、受信用の拾か配信用BOT、対象の部屋、不足する権限が表示されます。そのBOTのチャンネル権限を直し、開始をやり直してください。
- 拾が別のVCにいる場合は先に退出させます。拾を自動で奪ったり、壱〜玖へ受信を切り替えたりはしません。

- `/イベント中継 状態` の停止理由と受信時刻を確認します。登壇者がミュート中・客席にいる場合は声を受信しません。利用者側のスピーカーミュート、BOT音量、配信BOTへのサーバーミュートも確認します。
- ステージ終了、使っているBOTの移動・切断、必要な権限の喪失、受信BOTへのサーバースピーカーミュート、配信BOTへのサーバーミュートで全体を停止します。BOTを戻すだけでは再開しません。
- 受信の変換失敗、処理の遅延、最大20人を超える同時の非ミュート登壇者、6時間の上限でも停止します。遅れた音を何分も流し続ける動作にはしません。
- ネットワークやサーバー負荷に問題がある場合は、1部屋に減らして確かめます。BOTを再起動すると中継は止まり、自動では復帰しません。復帰は運営が開始コマンドを使います。
- Discordへの音声受信は `@discordjs/voice` の機能を使いますが、公式文書でも安定性が保証される機能ではありません。暗号化やDiscord側の変更を含め、**実通話で確認できないうちは当日の中継手段として確定しないでください**。聞こえないまま参加者に利用可能と案内しません。

## 音声の扱いと範囲

音声は短いメモリ上のバッファだけで扱い、録音ファイル・DB・音声内容のログを作りません。登壇者ごと最大120msの待ち行列、配信用に最大10パケットまでを保持し、過度に遅れる場合は止めます。発表の字幕・動画・配信先からの逆方向通話はありません。開始した運営IDと部屋IDは操作ログに残ります。

通常の読み上げは今までどおり投稿文だけを扱います。中継は運営の明示的な開始操作でのみ動作します。停止後、必要な部屋の読み上げは `/読み上げ 開始` で再開できます。
