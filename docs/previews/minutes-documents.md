# 議事録・音声から資料を作る（2026年11月15日）

本人の依頼は、議事録を入力して資料を作る機能を**社務所Webの管理画面に追加**すること。続けて「音声をいれたら自動で要約など（連携設定あり）」を指定。御朱印制度そのものの施行・本番合流・実Discord通知は今回行っていない。

## 入口と処理

`/minutes`の「議事録から資料を作る」→`/minutes/documents`。

- 音声：題名と20MB以下の音声を選ぶ→送信内容を確認→文字起こし→要約/決定/保留/作業/Q&A等の下書きまで自動処理。バックグラウンドで続き、一覧から復帰できる。社務所には原音を保存せず、文字起こしを原文として保存する。
- 文字：貼り付け、または保存済み議事録から原文を取り込んで保存。AIなしの見出し整理、または設定済みAIで自由文を整理する。見出し整理は独立した見出しの次行から分類し、文脈の意味を推測しない。
- 生成したものは下書き。概要・分類・項目・Q&A・手順を編集でき、原文の参照行と照合できる。順序が明確でない手順は補わず、必要なら手動で加える。原文は写しとして固定。文字起こし等を直す場合は別資料へ複製する。
- 保存済み本文をWord/HTML/Markdownへ出力。PDFは印刷用表示をブラウザーの印刷から保存する。原文の全文・原音は共有ファイルへ付けないが、本文へ入れた原文の抜粋は出力される。

## 権限・保存・連携

議事録の閲覧/操作権限とCSRFを使用。閲覧専用では生成・編集できない。新しい`0175_loose_the_executioner`に原文/本文/更新番号/予約状態を保存。作成nonceと更新番号/生成予約で二重登録・同じ版の二重生成・上書きを防ぐ。監査はID/更新番号/処理種類だけで、原文・音声・キーを記録しない。再生成失敗は以前の本文を保持し、音声の要約だけ失敗した場合は文字起こしから再試行できる。

失われた予約は2分後のアクセスで失敗状態になり、再試行できる。文字起こし前にサーバーが停止すると原音の再送が必要。入力は文字20,000文字/音声20MB、本文の項目80・Q&A60・手順12まで。音声処理は同時1件。AIのタイムアウトは文字起こし90秒/資料生成60秒で自動再送しない。

任意の`DOCUMENT_AI_API_KEY`と、`DOCUMENT_AI_MODEL`/`DOCUMENT_TRANSCRIBE_MODEL`をwebの環境変数に設定する。キー未設定では見出し整理を利用できる。実値は画面に出さない。固定のOpenAI APIだけへ送信し、資料生成では`store:false`。実APIの利用可能モデル・料金・データの扱いは運営の契約で確認する。詳細は`docs/deploy-vps.md`。

## 見本と再現

見本は**架空の会議と運営、メモリDB、代替AI/代替文字起こし**のみ。音声認識精度を実APIで検証した結果ではない。

1. Node22と依存関係を用意し、`npx tsx scripts/previews/minutes-documents.mts`を実行（127.0.0.1:4216）。実Discord・AI・本番DBへは接続しない。
2. `/fixture/login`で架空の議事録操作者として入る。`?readonly=1`で閲覧専用。新規会議の情報は架空のものだけを使う。
3. Chromium/Playwrightがある環境で`node scripts/previews/minutes-documents-browser.cjs`を実行。`PLAYWRIGHT_MODULE`でPlaywrightの場所を指定できる。
4. 確認後はサーバーを停止する。

fixtureのログイン/AI失敗/アプリ再生成/回数照会は確認用スクリプトだけのルートであり、製品へ存在しない。時刻を固定し、音声ファイルも確認用のダミー入力である。製品の実認識を示さない。
