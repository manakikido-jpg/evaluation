# 神殿スロット trial-2：初当たり前兆と通常天井

2026年11月1日。Draft PR120の続き。本番合流・一般公開・実財布接続は保留。

## 根拠と今回の範囲

Web取得が回復し、以下の凱旋の解析本文を確認した。新しい「神々の軌跡」の解析は混ぜていない。メーカー公表の内部抽選表ではなく、媒体の調査値を使う無料試遊モデルである。

- [なな徹：前兆ゲーム数](https://nana-press.com/kaiseki/machine/49/858/)：通常初当たりを4グループに分ける。ハズレ/下段黄7は最大24G、上段青7は12G、中段青7は16G、それ以外は24G。G-STOP・確定役の即時扱いを区別する。
- [必勝本：天井と設定変更](https://p.hisshobon.jp/machine/2529/1/52544)：1480Gと24G前兆、告知前の本前兆/G-STOP中の有効性、1%/80%を半々で選ぶ天井ループ。
- [一撃：天井と設定変更](https://1geki.jp/slot/milliongodgaisen/3/)：通常天井、前兆中も有効、天井ループの振分を照合。
- [必勝本：通常時のポイント](https://p.hisshobon.jp/machine/2529/1/51463)と[一撃：基本仕様](https://1geki.jp/slot/milliongodgaisen/64/)：ループは落選までGGを追加する仕組み。抽選開始Gは「次ゲーム以降」「当選したゲームから」と表記が異なる。試遊では次ゲーム以降に1回ずつ抽選する。前者の実戦上の古い天井/前兆概数は、専用解析の値へ混ぜない。

## 実装

`omenRules.ts`は通常の成立役による初当たり前兆表だけを持つ。公開の小数1桁の割合を10倍して整数の相対重みにした。合計100.3%/100.4%の丸めがあるため、これを内部の正確なウェイトとは呼ばない。出現しないG数を追加したり、最長Gへ丸め誤差を押し付けたりしない。

通常の役別当選率とmodeの3段階は引き続き仮の値。今回は「当選する率」ではなく「当選後に待つ長さ」を更新した。新規当選の次ゲームから減算し、最後のSTOPで確定する。残りGは保存し、再読込では再抽選しない。旧保存の残り3〜7Gも引き直さない。

通常天井は1480Gで`ceilingStocks`に基本1セットを確保し、`ceilingLeft`を24へ設定する。`ceilingHit`で同じ天井を繰り返し付与しない。`ceilingLoop`に1%または80%を保存し、次ゲームから落選まで1ゲーム1回だけ抽選する。当選済みセットと未消化のループ抽選は区別する。設定変更時の510/1000G天井とモード再抽選は今回は未実装。

**前段階の「本前兆中は天井を追加しない」という試遊処理を訂正した。** 当選告知前に到達した場合は、通常前兆の権利に天井分を加える。旧テストもこの根拠に従って変更し、重複STOPで天井が増えない検証を別に置いた。以前に失った権利を過去の履歴から補填する処理はない。

| 条件 | 試遊の扱い |
| --- | --- |
| 通常1479G→1480G | 即GGにせず、1セット確保＋24G前兆 |
| 通常前兆中に1480G | 元の権利と天井分を両方保持。先に告知されるGGへまとめて移す |
| 前兆終了Gと1480Gが同じ | 元の1＋天井1を保持して開始 |
| 天井前兆中のGOD | 天井分＋GOD5を保持。ループが当選済みならその分も保持 |
| 天井前兆中の赤7 | 天井分を保持してSGGへ。GGへ戻る際に移す |
| 天井ループがGG開始後も続く | 落選まで追加抽選を続ける |
| G-ZONE/通常へ戻るG-STOP | 天井カウンタに含める。GG/SGG内は増やさない |
| 天井前兆中の保存/別台再開 | 残りG・獲得権利・ループを引き継ぎ、受入台の状態と分離 |

同一ゲームのGOD/赤7と天井境界は、即告知の確定役を優先する試遊上の規則。長いHOLD等でG-STOP中に天井前兆が満了した場合も権利を保持し、現在のG-STOPを終えてからGGへ移す。この重複時の優先順位まで実機同等と確認した扱いにはしない。通常前兆の残りGは従来どおりG-STOP/SGG中に停止する。天井前兆は通常へ戻るG-STOP中も進め、SGG中は停止する。

旧trial-2の天井カウンタは保存済みの値を維持する。以前に数えていなかったG-ZONE/G-STOPの消化Gは復元せず、新しい消化分から数える。旧trial-1の抽選列・保存形式は維持する。

## 検証と残件

型チェック・ビルド成功。全220ファイル2,443件成功（686.00秒、`npm test -- --maxWorkers=3 --testTimeout=60000`）。関連6ファイル57件も成功。実行対象は同じ開発枝で、本番への統合・実稼働確認とは別。

`gaisenOmenRules.test.ts`で全重みの境界、契機別の最長G、1479/1480/24G境界、1%/80%の当落、通常前兆/GOD/赤7との重複、G-ZONE/G-STOP、途中保存・二重STOP・別台再開を検証する。`gaisenWeb.test.ts`では実ルートと使い捨てDBを通し、同時STOPが303/409になること、天井権利と実財布不変を確認する。

`pendingOmenSets`と試算の`unfinished.omenStocks`は通常前兆＋天井の未消化セット合計。`unfinished.ceilingStocks`はその内数で二重に足さない。残るループ率は未確定の追加抽選であり、獲得セットや払出には含めない。試算JSONには5ソースのハッシュと採用した前兆の重みを保存する。

表/裏モード、履歴当選の前兆、ストック発動時のA/B前兆、フェイク前兆、設定変更時天井、天井以外のループ、SGG-EX/メデューサ、G-STOP詳細は引き続き未照合または暫定。一般公開可能な収支・実機同等の完成版とは扱わない。
