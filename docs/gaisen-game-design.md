## 既存機能との接続案

運営専用の試遊と試算で確認した後に実銭へ接続する。通常の銭を使う試遊と無料見本を明記する。既存19ゲームの料金・確率・配当は変えない。

## 採用した初期配分と運用（2026-10-28）

直前に提示した配分・変更予約・通信復旧・グラフの識別を採用。以下の詳細設計には検討候補も含み、その箇所は明示する。

### 初期の5台

初期5台の設定は **1・1・2・2・4** を採用。台番号への割当は運営だけが確認できるようにする。設定5/6はイベント時の選択肢として残す。無料試遊の収支を見て配分を調整する。利益や還元率の保証ではない。無料試遊では全設定を順に試し、公開時の配分とは分ける。日替わりの自動変更は初期には行わない。

### 設定変更

- 社務所は「現在の設定」「変更予約」「反映状態」「変更履歴」を運営だけに表示する。一般用のAPI/HTMLへ内部値を埋め込まない。
- 変更は予約として受け付ける。通常時は着席権が終了した後、ボーナス中は本来のボーナスが終了した後の安全な時点に反映する。処理途中のゲーム/前兆中/G-STOP中などに割り込まない。
- 本人保存へ移したボーナスは保存時の設定を維持する。元の台はボーナスの権利を保存に移して解放するため、通常状態になった後に予約変更を反映できる。これは「途中でそのボーナスの設定を変える」処理ではない。
- 詳細設計候補：実際の設定変更時は実機に合わせて通常状態をリセットする方向。通常の離席/再起動ではリセットしない。天井が変わるため、リセット予定は一般にも表示するが、設定番号は知らせない。
- 保存ボーナスを受け入れる台は、通常状態と設定を退避する。再離席した場合も本人の進捗を保存して受け入れ台を復元し、ほかの人を長期占有させない。保存ボーナスは同時に1つだけ再開でき、保存がある間は新規の通常遊技より先にその続きを再開する。

### 保存と復旧

1. レバー、各STOP、区間の移行、保存/復元に操作IDと状態の版番号を付け、成立した結果と残高取引を整合する単位で保存する。二重クリック/別タブ/通信再送は同じ操作の結果を返す。
2. 回転中に通信が切れたら、再表示で同じ役・停止済みの位置から続ける。G-STOPは確定済みの各停止を保存し、未停止の分だけ次の操作で抽選する。既に払った分を再度払わない。
3. サーバー再起動では台・残りG・ストック・設定・本人保存を復元する。停止中は遊べないため、計画停止は確保時間を凍結し、障害停止は復旧後に停止時間を補正する方式を候補にする。
4. 整合が取れない台だけ新規操作を止め、社務所から状態/取引履歴を確認して復旧する。公開画面には「調整中」と表示。原因不明で自動的に全消去/全額返金しない。
5. 運営の復旧操作は実行者・対象・理由・変更前後・関連取引IDを記録する。残高の手修正は通常の復旧ボタンと分け、一度だけの補填取引として残す。

### 日別の公開データ

日本時間0時で「本日」を区切る。日付が変わってもゲームやボーナスはリセットしない。差枚は実払出と実投入の差を10銭単位で表示し、純増や獲得表示と混同しない。保存ボーナス再開分は実際に回した台の当日データに含め、「保存ボーナス再開あり」と区別する。元台や別台へ二重計上しない。GG初当たり、セット数、GOD/SGG回数は分けて集計する。

### 無料試遊の合格条件

通常→前兆→GG→G-ZONE、GOD、G-STOPの鏡/ホールド、SGG/メデューサ/EX、天井到達を個別に検証する。次に設定別の長期試算、短時間の収支分布、押し順成功/失敗、極端な連チャンを確認する。さらに通信切断・期限境界・同時着席・保存再開と再離席・設定予約・日付変更・障害復旧を検証する。試算値はゲーム数/試行数/ばらつきを併記し、実機同等の還元率を未検証で宣言しない。

## 採用した操作とテンポ

- 通常プレイはレバー→3つのSTOP。押し順ナビがある場面は大きく表示する。初期はオートプレイを実装しない。
- G-STOPは自分でSTOPを押して抽選し、オート停止しない。抽選はサーバーで行い、停止結果を保存する。通信再送で再抽選しない。
- 演出は通常/控えめ/即表示。抽選、押し順の判定、恩恵は演出設定で変えない。
- 離席時間はサーバーが受理した最後の有効なゲーム操作から計測する。ページ閲覧・再読込・ポーリング・音/演出設定の操作だけでは延長しない。
- G-STOP/SGG/G-ZONEはGGと同様に離席後1時間保護し、期限超過時の本人保存も区間の進捗を含めて行う。通常前兆の全てを1時間保護にすることは未採用。未解決の操作/確定済みの権利を失わないよう状態遷移を設計する。
- GOD、GG初当たり、SGG、連チャン数、獲得銭の履歴を確認できるようにする。獲得と差引収支は区別して表示する。
